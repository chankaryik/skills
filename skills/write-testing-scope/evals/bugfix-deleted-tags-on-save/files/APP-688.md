# APP-688 Drop deleted tags from the Automation editor before saving

The Automation editor keeps deleted tags in its unsaved changes and sends them again on every save. Deleted tags don't appear in the tag picker, so users can't remove them. Backend validation added in the last release rejects these saves with "Tag not found."

Drop tags from the editor once they're deleted, so the list that gets saved is correct. To reproduce: keep the editor open on an automation with an **Add tag** step, delete one of that step's tags in Settings, then save the automation.

A customer (Northwind Demo, workspace 10001) hit this on an automation their AI assistant built for them, with tags they then cleaned up in Settings. It's not specific to automations made by the assistant.

Workaround: hard-refresh the editor (Ctrl+Shift+R / Cmd+Shift+R), redo the unsaved changes, and save again.

APP-689 covers the backend side: ignore deleted tags on save. This frontend fix can ship with the next FE release.
